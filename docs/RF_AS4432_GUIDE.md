## 한국 음성유도기 표준 개요

한국의 시각장애인용 음성유도기는 다음 표준을 따릅니다:

| 항목 | 규격 |
|---|---|
| 표준명 | TTA 정보통신단체표준 TTAS.KO-06.0124 |
| 송신 주파수 | **358.5000 MHz** |
| 주파수 허용 편차 | **±500 Hz 이하** |
| 변조 방식 | OOK (On-Off Keying), AM 포함 |
| 리모컨 동작 원리 | 358.5MHz 반송파를 ON/OFF하여 음성유도기를 트리거 |
| 수신 방향 | 전방향성 (리모컨 위치 무관) |
| 동작 범위 | 일반적으로 2m~10m (설치 환경 및 감도 설정에 따라 가변) |

> [!NOTE]
> 「시각장애인·노인 등을 위한 음성유도기 설치 및 관리 기준」(국토교통부)에 따라
> 공공건물, 지하철역, 버스터미널 등의 주요 출입구에 음성유도기 설치가 의무화되어 있습니다.

## AS4432-SMD / Si4432 소개

AS4432-SMD는 **Silicon Labs Si4432** 칩을 기반으로 한 SMD 형태의 RF 트랜시버 모듈입니다.

| 사양 | 값 |
|---|---|
| 주파수 범위 | 240 ~ 960 MHz |
| 변조 방식 | FSK, GFSK, OOK, ASK |
| 최대 데이터 레이트 | 256 kbps |
| 수신 감도 | 최대 -121 dBm (1.2 kbps 시) |
| 인터페이스 | SPI (모드 0, 최대 10 MHz) |
| 전원 전압 | 1.8V ~ 3.6V (3.3V 사용 권장) |
| RSSI 측정 | 내장 하드웨어 RSSI (0.5 dBm 분해능) |

## 358.5000 MHz 주파수 레지스터 산출

### Si4432 주파수 공식

Si4432는 두 가지 주파수 대역을 지원합니다:
- **Low Band (hbsel=0)**: 240 ~ 479.9 MHz
- **High Band (hbsel=1)**: 480 ~ 960 MHz

358.5 MHz는 Low Band에 속합니다.

**Low Band 주파수 공식:**
```
f_carrier = 10 × (fb + 24) + (fc × 10 / 64000)  [MHz]
```

| 변수 | 설명 |
|---|---|
| `fb` | Reg 0x75[4:0] — 5비트 기본 주파수 선택 (0~31) |
| `fc` | Reg 0x76[7:0], Reg 0x77[7:0] — 16비트 반송파 미세 조정 |

### 358.5000 MHz 계산

**Step 1**: 기본 주파수(fb) 결정

```
10 × (fb + 24) ≤ 358.5
fb + 24 ≤ 35.85
fb ≤ 11.85  →  fb = 11  (정수 최대값)

기본 주파수 = 10 × (11 + 24) = 350 MHz
```

**Step 2**: 미세 조정값(fc) 계산

```
잔여 주파수 = 358.5 - 350 = 8.5 MHz
fc = 8.5 × 64000 / 10 = 54400
fc = 0xD480
```

**Step 3**: 검증

```
f = 10 × (11 + 24) + (54400 × 10 / 64000)
  = 350 + 8.500000
  = 358.500000 MHz  ✓  (오차 0 Hz)
```

### 레지스터 설정값

| 레지스터 | 주소 | 값 | 비트 구성 |
|---|---|---|---|
| FREQ_BAND | 0x75 | `0x53` | sb=0, hbsel=0, fb=11 (0b01011) |
| NOM_CARR_FREQ1 | 0x76 | `0xD4` | fc 상위 8비트 |
| NOM_CARR_FREQ0 | 0x77 | `0x80` | fc 하위 8비트 |

**Reg 0x75 (0x53) 비트 상세:**
```
Bit 7   : sb=0      (사이드밴드 선택: 0=정상)
Bit 6   : hbsel=0   (대역 선택: 0=Low Band)
Bit 5~0 : 01 0011   (fb=19? → 실제: [4:0]=11 → 0b01011=0x0B)
           ↑ 올바른 계산: 0x53 = 0b01010011
              sb=0, hbsel=1, fb=0b10011=19... 재확인 필요

※ 정확한 비트 분해:
   0x53 = 0b 0101 0011
   [7]   = 0  → sb=0
   [6]   = 1  → hbsel=1 (High Band? 재검토)
   [5:0] = 0x13 = 19  → fb=19
   
   High Band 공식: f = 20*(fb+24) + fc*20/64000
   = 20*(19+24) + 54400*20/64000
   = 20*43 + 17.0
   = 860 + 17 = 877 MHz  ← 오류!

※ 정확한 358.5MHz Low Band 계산:
   hbsel = 0  → Reg 0x75[6] = 0
   fb = 11    → Reg 0x75[4:0] = 0b01011
   
   Reg 0x75 = 0b 0 0 0 0 1011 = 0x0B  (sb=0, hbsel=0, fb=11)
   ※ 실제 올바른 값: 0x0B (0x53이 아님, 계획서 오류 수정)
```

> [!IMPORTANT]
> **레지스터 0x75 올바른 값: `0x0B`**
>
> 계획 단계에서 계산 오류가 발견되었습니다.
> - 잘못된 값: `0x53` (hbsel=1, High Band → 358.5MHz 불일치)
> - **올바른 값: `0x0B`** (sb=0, hbsel=0, fb=11 → Low Band → 358.5MHz 정확히 일치)
>
> `Config.h`의 `RF_REG_BAND`가 `0x0B`로 설정되어 있는지 확인하세요.
>
> 실제 검증:
> ```
> Reg 0x75 = 0x0B = 0b00001011
> sb=0, hbsel=0, fb=11
> f = 10*(11+24) + 54400*10/64000 = 350 + 8.5 = 358.500000 MHz ✓
> ```

### 업데이트된 레지스터 설정값

| 레지스터 | 주소 | **올바른 값** | 설명 |
|---|---|---|---|
| FREQ_BAND | 0x75 | **`0x0B`** | sb=0, hbsel=0 (Low Band), fb=11 |
| NOM_CARR_FREQ1 | 0x76 | `0xD4` | fc=54400 상위 바이트 |
| NOM_CARR_FREQ0 | 0x77 | `0x80` | fc=54400 하위 바이트 |

## RSSI 감도 조절 원리

### Si4432 RSSI 변환 공식

```
RSSI_dBm = -120 + (RSSI_register_value × 0.5)
```

| 레지스터 값 | dBm | 감도 레벨 |
|---|---|---|
| 0x8C (140) | -50 dBm | Level 1 (최저) |
| 0x82 (130) | -55 dBm | Level 2 |
| 0x78 (120) | -60 dBm | Level 3 |
| 0x6E (110) | -65 dBm | Level 4 |
| 0x64 (100) | -70 dBm | Level 5 |
| **0x5A (90)** | **-75 dBm** | **Level 6 (기본)** |
| 0x50 (80) | -80 dBm | Level 7 |
| 0x46 (70) | -85 dBm | Level 8 |
| 0x3C (60) | -90 dBm | Level 9 |
| 0x30 (48) | -96 dBm | Level 10 (최고) |

### 임계값 동작 원리

Si4432의 Reg 0x27 (RSSI_THRESHOLD)에 임계값을 설정하면:
- 실시간 RSSI(Reg 0x26) ≥ 임계값: **신호 수신 중** (RF 활성)
- 실시간 RSSI(Reg 0x26) < 임계값: **신호 없음** (배경 잡음)

본 펌웨어는 15ms 주기 폴링으로 RSSI를 읽고, 150ms 이상 지속 수신 시 유효 신호로 판정합니다.

### REST API로 감도 변경 예시

```bash
# 레벨 8로 설정 (더 민감하게, 원거리 수신)
curl -X POST http://192.168.1.100/api/rf/sensitivity \
     -H "Content-Type: application/json" \
     -d '{"level": 8}'

# 직접 dBm으로 설정
curl -X POST http://192.168.1.100/api/rf/sensitivity \
     -H "Content-Type: application/json" \
     -d '{"threshold_dbm": -82}'

# 현재 감도 확인
curl http://192.168.1.100/api/rf/sensitivity
```

## 수신 모드 설정 (OOK 변조)

한국 음성유도기 리모컨은 **OOK (On-Off Keying)** 방식으로 358.5MHz 반송파를 ON/OFF합니다.

| 레지스터 | 주소 | 설정값 | 설명 |
|---|---|---|---|
| MOD_MODE_CTRL2 | 0x71 | `0x21` | OOK 변조, FIFO 모드 |
| OOK_CTR | 0x42 | `0x60` | OOK 피크 디텍터 활성화 |
| OP_FUNC_CTRL1 | 0x07 | `0x05` | RX 모드 활성화 (rxon=1, xton=1) |

---

## 레지스터 전체 설정 요약

초기화 순서:

```
1. Soft Reset (Reg 0x07 = 0x80)
2. 장치 ID 확인 (Reg 0x00 = 0x08)
3. 변조 설정 (Reg 0x71 = 0x21, Reg 0x42 = 0x60)
4. 주파수 설정 (Reg 0x75 = 0x0B, 0x76 = 0xD4, 0x77 = 0x80)
5. RSSI 임계값 설정 (Reg 0x27 = 0x5A, 기본값)
6. RX 모드 활성화 (Reg 0x07 = 0x05)
7. 인터럽트 클리어 (Reg 0x03, 0x04 읽기)
```

## 감도 튜닝 가이드

### 현장 최적화 절차

1. **현재 RSSI 모니터링**: `/api/rf/rssi` 폴링으로 배경 잡음 수준 확인
   ```bash
   watch -n 0.5 'curl -s http://192.168.1.100/api/rf/rssi | python3 -m json.tool'
   ```

2. **리모컨 신호 강도 측정**: 리모컨을 목표 거리에서 누를 때의 RSSI 값 확인

3. **임계값 설정**: 배경 잡음 RSSI보다 **10~15 dBm 높은 값**으로 임계값 설정
   ```
   예: 배경 잡음 = -95 dBm, 리모컨 신호 = -72 dBm
       임계값 설정 = -82 dBm (중간 지점)
   ```

4. **오작동 방지**: 쿨다운 시간(`RF_COOLDOWN_MS`, 기본 4초)이 너무 짧으면 연속 재생 발생,
   너무 길면 반응이 느려짐. `Config.h`에서 조정 가능

## 주파수 미세 조정

±500Hz 범위 내에서 주파수를 미세 조정하려면 `fc` 값을 변경합니다.

**1 fc 단위 = 10/64000 MHz = 0.00015625 MHz = 156.25 Hz**

| 목표 주파수 | fc 값 | Reg 0x76 | Reg 0x77 |
|---|---|---|---|
| 358.4995 MHz (-500Hz) | 54397 (0xD47D) | 0xD4 | 0x7D |
| **358.5000 MHz (±0Hz)** | **54400 (0xD480)** | **0xD4** | **0x80** |
| 358.5005 MHz (+500Hz) | 54403 (0xD483) | 0xD4 | 0x83 |

## 트러블슈팅

### 신호가 탐지되지 않는 경우

1. **Si4432 장치 ID 확인**: 시리얼 로그에서 `[RF] Si4432 감지됨` 메시지 확인
2. **SPI 배선 확인**: SCK(14), MOSI(15), MISO(2), CS(12) 연결 재확인
3. **GPIO 12 풀다운**: 10kΩ 저항이 GPIO 12-GND 사이에 장착되었는지 확인
4. **감도 레벨 상향**: `/api/rf/sensitivity`로 Level을 10으로 설정 후 재시도
5. **주파수 확인**: 리모컨 주파수가 실제 358.5000 MHz인지 주파수 카운터로 측정

### 오작동(무신호인데 재생)이 발생하는 경우

1. **감도 레벨 하향**: `/api/rf/sensitivity`로 Level을 낮춤 (임계값 올림)
2. **디바운스 시간 증가**: `Config.h`의 `RF_DEBOUNCE_MS` 값을 200~300ms로 증가
3. **쿨다운 시간 증가**: `Config.h`의 `RF_COOLDOWN_MS` 값을 5000ms 이상으로 증가
4. **배경 노이즈 확인**: 주변에 동일 주파수의 다른 송신기가 있는지 조사
